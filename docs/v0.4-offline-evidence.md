# Attach your offline evidence

For leads/architects with an existing approved traceability report:

```sh
continuity evidence-attach --report traceability-v3.json --manifest evidence.toml --output report-v4.json
```

Omit --output for canonical JSON on stdout. The output must be a new file: existing files and inputs are never overwritten. Exit0 means success,2 invalid/unapproved inputs or arguments,3 sanitized I/O failure. No network, credentials, PAT prompts, document scans, test execution or inference. Only the two explicitly named bounded regular inputs are read; output is published atomically after validation.

Try the project-owned SYNTHETIC example:

```sh
continuity evidence-attach --report examples/v0.4-traceability-v3.json --manifest examples/v0.4-evidence.toml --output report-v4.json
```

Open report-v4.json in Explorer with Open JSON report. Overview now shows attached requirement/test/architecture metrics; Traceability shows explicit requirement-to-code paths and associated ADR/ICD/tests; Reviews & Verification shows separate reviews and historical test observations. Expand Attached requirement evidence for complete provenance, lookups, conflicts and limits. Search filters lists, never metrics. Header Export preserves the whole v4 report for reopening. The four primary areas, isolated synthetic scenario inspector, Atlas default and separate eShop validation sample remain intact. eShop without attachment legitimately has unavailable requirement evidence.

## Manifest contract

Primary format TOML; normalized JSON is an optional compatibility input selected only by .json suffix. See examples/v0.4-evidence.toml. Exact top-level manifest_version="1.0", publication_approved=true, collection. This approval is an explicit source-owner declaration for every alias/version/timestamp/hash/path/relationship; syntax does not establish publication permission or authenticity.

The collection has snapshot, boundary, collected_at, status, limits and arrays artifacts/associations/runs/lookups. New typed identity fields: kind, instance, scope, identifier, immutable version, document_kind (ADR/ICD for architecture, empty otherwise). Runs additionally declare exact test and target snapshot, aware timestamp, outcome and optional approved group. TOML empty strings represent null only in optional run group and lookup endpoint/relation/population. Other empty fields retain their typed validation. Times must be quoted ISO strings. All fields are explicit; unknown fields reject. The detailed example includes independent populations and endpoint lookups: COMPLETE/SUPPORTED is your collection assertion, not inferred from positive rows.

Legal explicit relations only: REQUIREMENT_WORK_ITEM, DOCUMENT_REQUIREMENT, DOCUMENT_COMPONENT, TEST_REQUIREMENT, VERIFICATION_TEST. Use full references, never title/name/path matching. Unknown WI/components remain unresolved. Requirement-to-WI alone is not implementation; it needs an existing valid qualified code path preserving original statuses/origins/supports.

Compute snapshot with Python snapshot_for(validated_traceability, approved_alias). It binds exact public canonical traceability bytes including provider/repository/revision, populations, lookups and component mapping. Example helpers and report-schema-v4.md explain APIs. Copy approved WI/component references from the existing traceability section. Enclosing report revision and declared directory depth must agree with code boundaries/configuration. Manifest stale fingerprint/repository/revision derives SNAPSHOT_MISMATCH/unavailable; no missing artifact is created. No-code v4 may carry observations but cannot qualify implementation/current-target execution.

PASS/FAIL are distinct declared historical exact-version/target observations; SKIPPED/UNKNOWN do not establish qualified execution. Same observation identity conflicts quarantine before retention limits; distinct PASS/FAIL run IDs both remain visible. Four dimensions have independent populations and unit denominators. No success rate, correctness, acceptance or readiness score.

Keep requirement/document descriptions, document/test content, logs/stack traces, reverse mappings, local paths, native DTOs, credentials/URLs and newly introduced employee data out. Whole v4 public boundary rejects unknown/private content including retained legacy fields. Reports with legacy private metadata need an explicitly approved public report; this command does not silently redact and claim completeness. Existing people evidence is preserved only through existing approved report fields, never added by this feature.

Limits: max8MiB per file, strict UTF-8, JSON nesting64, hard10,000 artifacts/runs and40,000 associations/lookups; soft canonical-prefix retention limits are explicit and preserve partial positives/conflict diagnostics. TOML/JSON duplicate keys, nonfinite values, malformed Unicode, unsupported versions/enums and forged derived results reject with fixed errors. Equivalent set input order and timestamp offsets canonicalize; semantic hop order is retained. Python/browser rederive and verify results. Source rights, alias/version authenticity, live compatibility and OS visual/mobile interaction remain MANUAL.
