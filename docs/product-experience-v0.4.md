# v0.4 product experience

## Product Owner decision (before architecture/development)

Target: engineering leads and architects inspecting a software system before a continuity conversation or technical handover. Current main `3986f15` has eight competing tabs, a stale v0.2 header, implementation-heavy tables and a disconnected requirements demo. The bundled eShop collection is a useful partial validation boundary but does not guarantee an instructive review story. Public HTML was fetched and matched current main; visual browser inspection is pending OS permission, not claimed.

Default: **Atlas Commerce · SYNTHETIC**, a fictional project-owned system with related component, implementation, review and requirement/test evidence. It provides an understandable first screen with known positive evidence and deliberate gaps. **Public eShop validation sample** remains a separate optional source and retains its documented partial collection. Imports are a third source: report-owned evidence must not be supplemented silently with showcase facts.

Journey: Overview explains the selected system/source, concentration, available review/implementation/requirement evidence and gaps. Continuity begins with components, then exposes historical contributor/file details and an optional contributor scenario. Traceability shows code connections and, for the synthetic showcase, related requirement/architecture/test paths. Reviews & Verification distinguishes PR interaction evidence from declared historical test observations. Inspectors retain original counts, qualification, status, exact versions, boundaries and raw provenance behind details. No combined readiness score.

Primary navigation: **Overview → Continuity → Traceability → Reviews & Verification**. Secondary contributor/file/scenario controls sit within Continuity. Requirements and test associations belong within Traceability; run observations also remain available from Reviews & Verification. Internal report/model/version terminology belongs in provenance/help, never primary navigation. Header says EXPERIMENTAL without a release claim.

Overview shows components, high/critical concentration and separate available coverage dimensions. Review overview counts distinct selected merged PRs with at least one qualifying effective review / selected merged PRs, labelled full-source historical coverage and collection status; component counts may overlap and are never summed into a global denominator. Requirements use existing four metrics unchanged. Absent evidence displays Unavailable with reason, never 0%. Empty supported evidence remains distinct from absent/failed evidence.

Reviews show component coverage/concentration, qualifying aliases and unreviewed PRs; excluded reasons and all source events are inspectable. Missing review data explains what reviews mean and how to obtain them, without implying zero reviews. Traceability/verification absence likewise explains unavailable evidence. Opening a showcase/example is an explicit source replacement, never an invisible merge. Changing a verification scenario changes only the visibly separate synthetic scenario inspector; the loaded Git report remains intact. For user/eShop reports, synthetic requirement evidence appears only in an explicitly opened sample inspector, not their overview.

Terminology: continuity concentration, historical contributors, implementation connections, declared test links, historical verification observations. VERIFIED means observed connection evidence; PASS is a declared observation for the exact test version and target, not correctness/adequacy/readiness. Missing evidence does not assert missing work; review coverage does not measure quality; people remain supporting evidence, never performance rankings.

Primary concise cards and human-readable path summaries precede expandable source/version/hash/lookup inspectors. Native keyboard-operable buttons/selects/details, labels, focus indication, wrap-safe navigation and horizontally scrollable tables are required. Visual/mobile/keyboard verification must be recorded honestly; structural tests do not claim OS visual validation.

Non-goals: scoring/review/traceability/verification mathematics changes; new report envelope/portable backend; live adapters/authentication; inferred relationship/title generation; employee scoring; release/version/tag; v0.5. The unfinished portable-report branch is separate and unpublished. Stable IDs FR415–420/AC419–424 are reserved by that work; this increment uses FR421–427/AC425–431 without reusing them.

PO exit: source behavior, journey/navigation, primary versus advanced evidence, empty states, safeguards and acceptance are explicit. Architecture and QA may proceed within this scope; no implementation approval is claimed.
