# v0.5 Executive Review UX

## Product journey

Engineering evidence → normalized evidence → engineering analysis → executive review → component investigation → exact evidence.

The public landing introduces this journey and directs first-time users to the **SYNTHETIC DEMO PROJECT**. Real Azure DevOps reviews are generated locally with `continuity engineering-review`; the static public site never requests a PAT or represents an Azure connection.

## Information architecture

The primary journey is Start a Review, Executive Review, Components, Engineering Details, then Evidence & Methodology. The existing Technical Explorer remains available as a secondary path for detailed Git, traceability, review and verification inspection.

## Report presentation

`engineering-review-1` remains normative. `engineering_html.render` validates and recomputes that package before presentation. HTML only converts accepted units and labels; it does not calculate metrics or create findings. The executive screen shows four derived cards: Continuity, Delivery, Defects and Builds, followed by accepted findings and an exact-bound component table.

Component selection matches an exact displayed component name. A traceability chain is shown only when accepted evidence terminates in the identical component reference/configuration. Missing evidence remains Unavailable; absence of an attention finding is never rendered as Healthy.

The desktop review uses a compact dark navigation rail and a single white content surface. Its header carries the system, provenance badge and assessment period. Immediately after the header, the first review content is the four executive cards; historical-source context follows those cards rather than displacing them. Attention is visually distinct from unavailable data: HIGH uses the reserved red treatment, ATTENTION uses amber, and Unavailable has no positive colour or health implication.

## Synthetic and genuine behavior

Atlas Commerce is always labelled **SYNTHETIC DEMO PROJECT**. It is an interactive, offline example. Genuine locally generated reports use the same renderer and semantics, use their approved system alias and assessment period, and never fall back to Atlas data.

## Responsive and print behavior

Desktop uses a compact navigation shell and content surface. Narrow layouts stack cards and retain horizontal scrolling for tables. Print removes navigation and actions while retaining executive summary, components, engineering details and human-readable evidence. No raw JSON is shown in ordinary report views; it remains downloadable as the audit package.
