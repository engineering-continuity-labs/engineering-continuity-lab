# v0.5 Executive Review UX

## Product journey

Engineering evidence → normalized evidence → engineering analysis → executive review → component investigation → exact evidence.

The public landing introduces this journey and directs first-time users to the **SYNTHETIC DEMO PROJECT**. When launched through `continuity explorer`, the primary local path is a repository path or an HTTPS Git clone URL, including an Azure DevOps Server/on-prem Git URL. That one-action route clones/analyzes Git history only; it does not acquire Azure work items/builds or ask for a browser PAT. The browser never accepts URL credentials, though Git may use an already configured local credential manager. The public static site directs users to start that loopback explorer and never represents an Azure connection.

## Information architecture

The primary journey is Start a Review, Executive Review, Components, Engineering Details, then Evidence & Methodology. The landing has two explicit starts: **Explore Atlas Commerce** and **Use your engineering evidence**. Atlas opens in the same ECL application flow (not a separate site or popup) and carries the identical generated-report navigation labels. The existing Technical Explorer remains available as a secondary path for detailed Git, traceability, review and verification inspection.

## Report presentation

`engineering-review-1` remains normative. `engineering_html.render` validates and recomputes that package before presentation. HTML only converts accepted units and labels; it does not calculate metrics or create findings. The executive screen shows four derived cards: Continuity, Delivery, Defects and Builds, followed by accepted findings and an exact-bound component table.

Component selection matches an exact displayed component name. A traceability chain is shown only when accepted evidence terminates in the identical component reference/configuration. Missing evidence remains Unavailable; absence of an attention finding is never rendered as Healthy.

The landing and desktop review use the same compact dark navigation rail and white content surface. The landing rail switches from Start a Review into the same Executive Review, Components, Engineering Details and Evidence & Methodology vocabulary; the technical explorer remains secondary. The review header carries the system, a plain-language data-source label, provenance badge and assessment period. Immediately after the header, the compact Start here layer precedes the four executive cards; historical-source context follows those cards rather than displacing them. Attention is visually distinct from unavailable data: HIGH uses the reserved red treatment, ATTENTION uses amber, and Unavailable has no positive colour or health implication.

### Layered executive read

The Executive Review uses three reading layers without changing the accepted package or the ER01–09 finding semantics. Directly beneath the report identity it renders **Start here**: at most three deterministic accepted finding groups in the existing evidence-order, each linked to its retained inspection anchor. **At a glance** then exposes the exact four independent executive dimensions. The complete finding inventory, components and methodology remain reachable through the existing links and navigation. This is prioritised presentation, not a new priority metric, recommendation engine, combined score or substitute for unavailable evidence.

## Synthetic and genuine behavior

Atlas Commerce is always labelled **SYNTHETIC DEMO PROJECT**. It is an interactive, offline example. Genuine locally generated reports use the same renderer and semantics, use their approved system alias and assessment period, and never fall back to Atlas data.

## Responsive and print behavior

Desktop uses a compact navigation shell and content surface. Narrow layouts stack cards and retain horizontal scrolling for tables. Print removes navigation and actions while retaining executive summary, components, engineering details and human-readable evidence. No raw JSON is shown in ordinary report views; it remains downloadable as the audit package.
