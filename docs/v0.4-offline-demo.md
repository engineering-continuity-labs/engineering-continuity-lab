# v0.4 offline evidence demo

Open the [published explorer](https://engineering-continuity-labs.github.io/engineering-continuity-lab/) and select **Evidence v0.4**. Choose BASE, PARTIAL, STALE_TARGET, CONFLICTING_RUN, EMPTY, UNSUPPORTED, FAILED or LIMIT. The demo uses bundled, project-owned synthetic declarations; no real tests execute and no network acquisition occurs.

BASE shows 2/4 in each of requirement-code, requirement-test, requirement-architecture and executed-test coverage. Qualified historical PASS, FAIL, SKIPPED and UNKNOWN counts are each 1. FAIL counts as execution evidence, not success; skipped/unknown observations do not count as executed tests. Coverage does not assert correctness, readiness or architecture adequacy.

Expand paths, run observations and snapshot/lookup provenance to inspect exact versions, target revision/fingerprint, explicit origins, gaps, exclusions and completeness. Empty/unavailable coverage remains null. Conflicting run identities are quarantined rather than resolved to a convenient outcome.

**Export synthetic evidence** downloads the isolated `v0.4-demo-1` artifact. It is not an importable Git report envelope. The existing Git report export and v1/v2/v3 importer remain separate. No general v0.4 importer, CLI, live adapter, release or package version change is included.

From a checkout, run `python scripts/generate_v04_demo.py --check` to verify the bundle against current Python derivation. Run `python -m http.server 8000 --directory ui/dist` and open `http://localhost:8000` for the local demo. Source aliases require human approval before any real evidence is published; recognized private material is rejected, but aliasing is not confidentiality certification. Visual, keyboard and responsive browser checks remain MANUAL when computer-use permission is unavailable.
