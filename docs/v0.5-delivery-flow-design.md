# v0.5 Delivery Flow — Architect handoff

Design only, input FR503/505–507/510/512 and PO time/sampling policies. No new provider/domain/metric/runtime code in this PR. Acquisition → bounded public normalization → pure flow analysis → assessment is separate from existing traceability analysis. Existing v4 code evidence is a read-only dependency, never a mutable delivery store.

## Normalized collection and identities

`delivery-evidence-1` conceptual envelope: schema/rule version; approved system/repository/project aliases; collection alias/retrieved_at; independent population selections; field/history/window-specific coverage; source profile + selection/state-mapping/component-mapping fingerprints; records; observed explicit component memberships; diagnostics/exclusions. No native DTO/connection settings/person fields. Typed identity `(kind, provider_alias, instance_alias, scope_alias, identifier_alias)` distinguishes WORK_ITEM, PR and BUILD. A record also declares source observation/revision identity and observed_at; contradictory payloads for the same exact observation identity are quarantined before truncation, never select latest/favorable values. Distinct immutable revisions/history events remain legitimate observations.

WorkItem: approved reference/type alias; created_at nullable; state alias plus configured category OPEN/COMPLETE/REMOVED/UNKNOWN; state_as_of; optional independently observed transitions `(event_alias, sequence, occurred_at, previous_state, next_state)`; optional explicitly configured start/completion field observations with field-policy fingerprint. History coverage declares start/end, initial-state availability, capability and completeness. Do not emit assignee, title, description, author or reverse mapping. Missing creation is unknown, not epoch0.

PR: approved exact provider/repository reference; created_at nullable; state OPEN/MERGED/ABANDONED/UNKNOWN; state_as_of; explicit merged_at nullable and actual merge outcome; approved source revision where available. Completion of an abandoned PR is not merging. v0.2 merged-only review populations cannot supply open-PR inventory or all delivery PRs; delivery independently enumerates them.

Build: approved BUILD reference and definition/pipeline alias; explicit repository/scope/source revision; queued_at/start_at/finish_at nullable; observed status; result SUCCESS/FAILURE/PARTIAL_SUCCESS/CANCELED/UNKNOWN. Native partiallySucceeded maps PARTIAL_SUCCESS, never success or failure. Definition and repository selections are explicit. In-progress runs remain visible, excluded from terminal result fractions/duration; queued-only values never substitute for start time. Retry run identities count separately; duplicate pages do not.

## Shared temporal and qualification contract

All instants are aware ISO Gregorian timestamps normalized to UTC microseconds; reject missing zone/invalid calendar/nonfinite durations. Retain source timestamp precision policy (Azure7 fractional digits reduce to microseconds consistently with existing transport, no invented precision). Intervals half-open `[start,end)`, exact-boundary event belongs to next interval. `assessment_as_of` is explicit and must be at/after current.end and no later than retrieval instants used for inventory. Default end = UTC midnight at/before assessment_as_of; current=end−30days..end, previous=end−60days..end−30days. Explicit current.from/current.to use equal preceding duration unless previous is supplied; reject nonpositive duration, overlap, gap or unequal elapsed seconds. Selection range max3650days, no implicit local timezone/DST calendar adjustments. Display UTC and source precision.

Inventory is state **immediately before end**: events at end are excluded. Snapshot-only inventory requires source-declared state_as_of representing this exact boundary policy, not live retrieval state relabelled as a historical inventory. Otherwise use a complete history prefix with known initial state through that boundary; missing predecessor/initial state makes historical inventory unavailable. Source retrieval >=end does not imply historical reconstruction or atomicity. Current and previous inventories independently qualify. Creation must be<=inventory instant; future dates, completion<start, nonmonotone sequence/times and state/endpoint contradiction quarantine affected identities/fields with fixed diagnostics.

Transition ordering uses explicit monotonically ordered provider sequence/revision, with nondecreasing UTC instants; absent/tied sequence with contradictory transitions is conflict, not identifier tie-breaking to invent history. History truncation/gaps retain observed events but cannot prove a first/last transition or absence. A named timestamp field can support duration only when its source declares its exact start/completion meaning and selected episode identity; arbitrary ChangedDate/current state is not a substitute. Such fields do not establish an independently enumerated historical completion-event population.

A flow policy defines selected WI types, start states/field, completion states/field, removed states and fingerprints. A qualified history episode begins at first selected start entry after creation or after exiting the preceding completion; repeated OPEN/active states do not reset its clock. It ends at the first selected completion entry after that start. Reopen starts a new candidate episode; no selected start→duration unavailable, no completion→censored open observation (not0). For a window's per-WI completed-duration sample select the **last qualified completion episode in that window**, once per distinct WI, with complete episode/history coverage required to establish that selection. Additional episodes remain inspectable but do not weight quantiles repeatedly. An explicit single start/completion pair with immutable episode identity may support that pair only; absent full-window episode enumeration makes representative per-WI sample partial/unavailable, not a complete sample.

## Metrics and reproducibility

| Dimension | Unit / formula / qualification |
| --- | --- |
| WI completed throughput | Distinct selected WI with at least one explicit completion entry in window. Complete result requires independent eligible WI + completion-event enumeration over full window; snapshot latest completion date alone is insufficient. Removed is excluded, not completed. |
| Open WI count/age | Independently selected WI classified OPEN at inventory boundary; each age=(end−created_at)/86400 elapsed days when both qualify. Null age with missing creation; show eligible/unknown/excluded. |
| WI cycle distribution | One representative qualified episode per completed WI/window as above; elapsed completion−selected start. No implicit creation fallback: CREATED start only if explicitly configured in policy. |
| Merged PR throughput | Distinct selected PR with state MERGED and explicit merge timestamp in window; independent merged-event enumeration including later state/history limitations declared. |
| PR lead distribution | One merged PR duration merged_at−created_at with both explicit nonnegative instants; author identity irrelevant. |
| Open PR age | Selected OPEN inventory at boundary, age from explicit creation; current retrieval snapshot is not historical end state. |
| Build counts/results | Distinct terminal build runs with finish_at in window; explicit success/failure/partial-success/canceled/unknown categories plus excluded unfinished/undated counts. Successful/failed fractions denominator = terminal runs with known SUCCESS/FAILURE/PARTIAL_SUCCESS/CANCELED, UNKNOWN excluded/count disclosed. Empty denominator=null. |
| Build duration | finish_at−start_at for qualified terminal runs; queue delay separate unimplemented candidate, never combined into duration. |

Every metric: key, units, window/inventory, population selection/fingerprint, observed count, qualifying count, selected/unknown/excluded counts/reasons, value/null, metric availability OBSERVED/PARTIAL/UNAVAILABLE, capability, collection completeness, source references and rule/version. Collection COMPLETE means enumeration coverage, not field adequacy; missing/conflicting required fields make the affected metric PARTIAL or UNAVAILABLE independently. Supported complete empty event count is0; empty age/duration/ratio is null EMPTY_POPULATION. Unsupported/failed selection without usable evidence has null, never0. Partial surviving counts are observed lower-bound/subset counts, not population totals or predictive rates.

Durations/ages are stored integer microseconds, display days/seconds only; no premature rounding. Sort values ascending, median average of middle pair (retain rational numerator/denominator microseconds when half-integer); p75/p90 nearest-rank `sorted[ceil(p*n)-1]`. Minimum n: median1,p75=4,p90=10. Report n, valid/unknown counts, exact sample refs, no interpolation/extrapolation or summary for below-minimum sample. A metric with exclusions can show observed sample summary PARTIAL; it cannot feed a complete-comparison finding.

Age buckets per policy default `[0,7)`, `[7,30)`, `[30,90)`, `[90,∞)` days; unknown age is separate. Threshold-aged default>=30 elapsed days, configurable explicit policy. Rows partition known-age units, unknowns retained. Current open items are right-censored; completed duration distribution excludes open work, with open inventory shown alongside it. Neither distribution describes individual productivity.

Trends require matching system/provider scope, work-item type/state/start policies, build definition selection, component policy, event unit, precision and equal contiguous windows; immutable selection definitions must match, population membership may naturally change. Both metrics must be OBSERVED with COMPLETE required enumeration/fields and n>=4 for median comparisons (p90 n>=10); otherwise trend=null with mismatch/completeness/sample reason. Absolute delta=current−previous, duration unit preserved, fraction delta in percentage points; relative delta only previous>0, previous0 produces null BASELINE_ZERO. Previous0/current0 count delta0 is observable without a relative percentage. Report observation direction, not better/worse until an explicit fixed finding rule applies. No calendar normalization to unequal windows.
