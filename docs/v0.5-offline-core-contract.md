# v0.5 offline core implementation contract

Architect clarification of the approved design; no product scope change.
HTML/manager UI, a user CLI and Azure acquisition remain subsequent increments.

## Input boundary

`continuity.reporting.engineering_review.compose` takes explicit assessment ID,
system and `Windows`, plus optional public `ecl_report`, delivery and quality
objects. Missing objects produce unavailable dimensions. The normalized
collections have `delivery-evidence-1` or `quality-evidence-1` versions, an
explicit publication assertion, approved aliases, retrieval time, policy and
selection fingerprints. Publication rights and source authenticity remain
manual assertions; syntax and hashes do not prove either.

Independent population coverage for `work_items`, `pull_requests` and `builds`
declares capability, collection status, provider, instance, scope and repository.
References must match their population's provider/instance/scope. Work items
declare selected type, immutable observation alias, history capability and
coverage, initial state and ordered transitions. CREATED-start is explicit.
Dates normalize to UTC; duration values retain integer microseconds and exact
rational medians. Quality uses created/reopen start policy; it never infers
reopening from a snapshot.

Priority and severity have separate approved category maps and fingerprints.
A category observation is qualified only at its explicit `category_as_of`
matching the inventory boundary. Absent historic category values cannot be
backfilled from a current observation. Unknown categories are disclosed;
unsupported categories and failed empty acquisitions yield null counts.

## Immutable observations and qualification

Equal observations count once. Conflicting payloads sharing an observation
identity quarantine the entity. Distinct lifecycle observations may extend an
exact common history prefix; known complete prefixes must not omit a later
observation's events before their end. Different starts, creation facts or
incompatible histories are excluded with partial qualification, rather than
selected by recency/outcome. All original observations remain embedded.

PR observations retain source boundary states separately from an explicit
consistent merge event. Only a snapshot at the selected inventory boundary
supports inventory. Contradictory creation, merge or boundary state facts are
excluded. Build runs have distinct identities and explicit terminal outcomes;
unknown results are excluded from fractions and disclosed. Missing starts do
not qualify a complete duration distribution. Ratios from partial evidence are
observed-subset ratios, never population estimates.

Comparisons require complete qualified samples from the same immutable
selection and policy, contiguous equal windows and minimum sample sizes.
Per-population acquisition completeness does not certify field or duration
adequacy. All new findings use fixed versioned thresholds and artifact-oriented
investigation IDs; no overall score or causal explanation is produced.

## Component memberships

Declared memberships name exact record and existing validated component refs,
mapping ID, source boundary and completeness. The collection declares mapping
revision and complete-lookup assertion. Binding requires the exact component
from the imported traceability result, a resolved traceability boundary, matching
boundary/report/mapping revision and matching selected population/component/
boundary repository. Component configuration is part of exact reference equality.
Missing/incompatible bindings are reported unresolved and prevent component
negative totals. Global metrics retain unmapped entities; overlapping rows
must not be summed. Memberships do not modify old trace paths.

## Machine output and QA

The separate `engineering-review-1` package embeds normalized sources and
preserves the old report. SHA256 source digests provide integrity. Import uses
strict JSON, recomposes results and rejects changed metrics, refs, findings or
unknown fields. Each input is bounded to 8 MiB, package to 32 MiB, depth to 64,
records to 10,000 per population, events/memberships to 40,000, findings to
10,000 and finding support references to 40,000. No automatic
soft truncation is implemented; excessive input fails with a sanitized error.

QA source oracle and boundary regressions live in
`tests/test_engineering_review.py` and `tests/test_engineering_review_package.py`.
The explicit SYNTHETIC provider contains the accepted 4-WI-per-period, six-Bug
and four-build source events. It cannot certify live Azure compatibility.
Runtime acceptance is partial until complete relevant tests, independent review
and final-head CI are recorded; manager rendering and live profiles remain
PLANNED/MANUAL respectively.
