# v0.4 evidence design: offline extension

Architect input: FR401–412/NFR401–406. The original design-only PR changed no runtime. This offline increment implements the contract and isolated synthetic demo below.

## Ownership and boundaries

Add a separate JSON-agnostic v0.4 normalized collection and pure derivation module. Do not extend v0.3 enums implicitly: current v0.3 constructors/serializers/browser reject unknown artifacts as before. A v0.4 context references a complete immutable v0.3 evidence/report snapshot by explicit approved snapshot identity, repository scope and exact source revision. Context validation checks these against the supplied snapshot, not merely a display label. Existing v0.3 report derivation remains semantic authority for code chains.

New references carry kind, approved instance/scope/artifact alias and immutable version. Architecture documents additionally declare ADR/ICD subtype. Verification observations have their own exact identity/version and explicit test-version/target-snapshot/revision join plus aware collection/run times. Matching has no name fallback, hashing-as-confidentiality shortcut or latest-run selection. Required version/target fields invalid or absent produce bounded scoped diagnostics and cannot support qualified execution; acquisition failure remains separate from outcome UNKNOWN.

The adapter-facing collection owns independently enumerated requirements/documents/tests, explicit associations, observations, lookups and boundaries. Native ingestion/resolution and publication approval belong to future adapters, never core. Collection and lookup statuses follow existing vocabularies but belong to this extension's populations and relations. Contradictory same scoped observation identity is quarantined; multiple different run observations for the same test remain distinct with their outcomes, without deriving a single current success result.

## Legal relation/path grammar

| Relation | Source → target | Authority |
| --- | --- | --- |
| REQUIREMENT_WORK_ITEM | Requirement → exact v0.3 WI reference | Explicit observed |
| DOCUMENT_REQUIREMENT | ADR/ICD → Requirement | Explicit observed |
| DOCUMENT_COMPONENT | ADR/ICD → exact v0.3 Component reference | Explicit observed |
| TEST_REQUIREMENT | Test → Requirement | Explicit observed |
| VERIFICATION_TEST | VerificationEvidence → Test exact version | Explicit observed; outcome qualification additionally matches target snapshot/revision |

Requirement implementation projection may concatenate REQUIREMENT_WORK_ITEM with one existing supported v0.3 WI-to-component path, preserving all hop origins, qualified gaps and both snapshot boundaries. Longest supported path has six nodes/five hops (Requirement, WI, PR, Commit, ChangedPath, Component); existing shorter code paths remain shorter. Document and test relations are not traversed as arbitrary bidirectional graph edges. Verification→Test→Requirement is at most three nodes/two hops and never becomes implementation evidence. Documents do not prove code compliance. Component references absent from the linked v0.3 snapshot are unresolved, never manufactured by this extension.

## Coverage semantics

Derivation forms distinct eligible artifact sets from independent selected populations; links do not expand denominators. Exact scope/version/target qualification precedes membership. Requirement implementation numerator uses only a VERIFIED v0.3 code path with the explicit requirement join; a valid positive path may coexist with PARTIAL collection. Test/document numerator requires a valid explicit association to an independently observed exact-version target. Qualified execution numerator includes tests with any exact qualified PASS or FAIL observation; SKIPPED/UNKNOWN do not count as executed. Conflicts/mismatched target observations contribute no qualified execution and remain visible with excluded reasons. Distinct eligible units count once; run outcome counts count distinct retained qualified observations independently.

Each dimension computes availability/completeness from its own required populations/relations and the joined snapshot where relevant. Missing/unsupported lookups yield null fraction, while known positive numerator and independently observed denominator remain available as counts. Complete supported denominator zero also yields null with EMPTY_POPULATION. Incomplete supported evidence may show observed fraction and PARTIAL status; it never proves absent relations MISSING. A FAILED collection without usable evidence cannot emit observed zero as complete coverage. No cross-dimension score or latest outcome rule.

## Rollout and risks

First runtime increment: new immutable values, strict normalization, pure derivation, synthetic fixture and tests. Future serialization requires an explicitly reviewed extension schema/envelope plus coordinated Python/browser consumers; do not relax v3 validation preemptively. UI and acquisition follow separate implementation increments within accepted intent. Provider/CLI acquisition remains deferred. The isolated synthetic Explorer tab now displays these kinds without extending the Git report envelope.

Risks: version aliases may be caller-declared rather than cryptographically authenticated; source owner attests identity/publication, which remains MANUAL. Non-atomic source snapshots and outdated test target revisions yield explicit unresolved/excluded evidence, not a certified PASS. Multiple legitimate runs may disagree. Negative conclusions require trustworthy complete enumerations; source approval and live compatibility cannot be inferred from synthetic fixtures.

## Offline core + isolated synthetic demo contract (Architect, before runtime)

V04-N01 entry gate: soft limits default to 1,000 selected artifacts,4,000 associations,2,000 run observations and10,000 projected code paths. Valid override ranges1–10,000 artifacts/runs/paths and1–40,000 associations. Hard input safety bounds10,000 selected artifacts total,40,000 links,10,000 observations,40,000 lookups; exceeding hard bounds rejects input safely. First normalize conflicts/deduplicate the hard-bounded input, then order by full typed/scoped/version identity and retain the canonical prefix at soft limits. Scoped conflict identities never reappear after truncation. Exhaustion adds a fixed LIMIT_EXHAUSTED diagnostic and PARTIAL completeness; denominators explicitly describe retained independently observed populations, with dropped counts recorded. Limits do not invent completeness or missing negatives.

Snapshot identity is an approved alias plus exact repository/revision and SHA256 fingerprint of the existing canonical public v0.3 traceability section. Derivation recomputes the digest and checks all declared boundary repository/revision and referenced WI/component membership. Digest verifies byte identity of already-public evidence; it is not a confidentiality mechanism or publication approval. Invalid snapshot joins produce diagnostics/unavailable code qualification while other independent test/document associations may remain valid. Domain types remain JSON-agnostic; the analysis boundary uses the existing public serializer for digest validation.

New collection lookup keys: population (REQUIREMENT,TEST,ARCHITECTURE_DOCUMENT), or typed endpoint/relation/direction. Source lookup OUTBOUND and inverse target lookup INBOUND follow the declared grammar. Complete support for a dimension requires its independently selected populations plus every eligible relation endpoint lookup; absent/unsupported/failed lookup makes the fraction unavailable. Conflicting same-run identities taint related verification lookups only. Collection-wide invalid/limit diagnostics conservatively prevent MISSING while retaining valid positives.

Demo rollout is deliberately isolated: a generated project-owned synthetic artifact has `schema_version: "v0.4-demo-1"`, not a Git report envelope/version4. A separate Evidence v0.4 tab shows only this bundled build-generated snapshot and selectable BASE/partial/stale/conflicting/empty scenarios. Existing v1/v2/v3 upload/export remains owned by existing model validators and cannot import this artifact. Demo export is clearly labelled and separate; no generic v0.4 import/API/CLI/live adapter is claimed. Python derives and serializes each scenario; checked-in module is compared to fresh derivation in tests. Browser presentation does not recalculate coverage/qualification. All safe dynamic text escaped; no links to native providers/credentials/people scores. Display all four coverage dimensions, exact outcome counts, requirement-code paths/underlying origins/gaps, test/document associations, qualified/excluded runs and snapshot provenance. This is an executable synthetic demo, not real test execution.

Partial population evidence cannot establish MISSING; retained positive explicit links remain usable. Every code boundary must declare the same exact revision/repository; absent or conflicting revision invalidates the join without discarding independent test/document links. Shared existing path serialization is extracted without wire changes so projections preserve every support origin, gap, boundary and rule. Legacy UI references show provider, revision/context, mapping configuration and hash algorithm.
