# Engineering System Review — composition design

Architect input: [PO contract](../specs/v0.5/product-spec.md), accepted four-area product experience and immutable v4 public evidence. Status PROPOSED/design only. Delivery/quality definitions: [Delivery Flow](v0.5-delivery-flow-design.md), [Quality](v0.5-quality-evidence-design.md). No runtime/UI/acquisition added by this PR.

## Composition and output ownership

Validated v1–v4 ECL report + optional normalized delivery/quality collections + explicit review policy/windows → pure deterministic assessment → existing browser manager presentation / standalone printable HTML. No direct provider/network call inside composition. Missing input generates an explicit unavailable dimension; it never loads Atlas behind a user's report. Existing source identities, model/report/rule versions and metrics remain unchanged. Old evidence reference/as_of may precede the review period; display HISTORICAL_SOURCE_BOUNDARY and never imply it measures this window. Independent dimensions can coexist without a cross-service atomic snapshot.

Proposed machine artifact: `schema_version: "engineering-review-1"`, `assessment_id` (approved alias), `system`, `assessment_as_of`, `windows`, `policy`/fingerprints, `evidence_sources`, `dimension_results`, `component_results`, `findings`, `investigations`, `completeness`, `limitations`. Source entries carry role, approved source/collection alias, underlying schema/rule/model, canonical SHA256 digest, scope, retrieval/observation interval and declared mapping/selection. Metric entries use the reproducibility structure in Delivery; legacy metrics are references plus unchanged values/status and exact provenance, never copies with new rule semantics.

Assessment is a separate layer, not report_version5.0 or mutation of report4.0. A conceptual portable package supplies `{assessment, evidence:{ecl_report,delivery?,quality?}}` as validated allowlisted public objects with immutable digests/references, sufficient for offline audit. Referential integrity and result recomputation are required on import; a digest is integrity, not authentication/publication rights. Missing source may be declared unavailable without a digest; dangling evidence refs/contradictory metrics reject, not silently pass. Unsupported future schema/types reject. Canonical set ordering follows full scoped identities and Unicode code points; ordered support/history sequences retain order, UTC timestamp/finite rational duration semantics follow the source contracts. Same inputs/policy produce same JSON/findings/order; no generated wall-clock ID/time, LLM prose or last-response selection.

Future bounds: strict UTF-8, duplicate-key/nonfinite/lone-surrogate/unknown-field/enums rejection, depth64, max8MiB each ECL/delivery/quality input and max32MiB validated assessment+embedded public package/HTML. Hard10,000 records per new population,40,000 history events/explicit memberships per collection,10,000 findings,40,000 evidence refs; inherited v4 bounds stay unchanged. Canonical soft retention must diagnose PARTIAL before any negative inference, never resurrect conflicts. If embedded output exceeds bounds, reject fixed error (do not drop evidence but call it self-contained); future separate bounded external bundle is a different explicitly designed capability. Errors never echo raw source/path/credential data.

Human artifact contains all twelve PO sections, compact first screen, component drilldown, rule/evidence inspection and limitations. Existing four-area navigation remains; precise manager-entry placement is future PO-approved UI work, not runtime in this PR. Self-contained HTML embeds safe normalized package/assessment, inline CSS and minimal optional scripts, no remote fonts/scripts/fetch/telemetry, and supports semantic native keyboard controls, focus and print CSS. All dynamic text escaped; JSON data serialization must prevent `</script>`/markup breakout. Human text is fixed template + escaped evidence values. Browser print-to-PDF is user capability, no native PDF engine/dependency. JSON is normative; HTML cannot recompute alternate scores or hide exclusions to fit first screen.

## Component joins and landscape

Canonical component identity is existing `(repository, strategy, configuration, component identifier)`; alias display alone never equality. Flow/defect/build-to-component membership is either an exact existing validated path into the explicitly referenced traceability snapshot, or an explicit source-owner assertion `{record_ref,component_ref,mapping_id,origin:DECLARED_MAPPING,boundary,completeness}`. It is a presentation/aggregation membership, never inserted into v3/v4 trace paths as observed code implementation. Exact scoped repository/config/snapshot compatibility is mandatory; unsupported/mismatched mapping remains unavailable. Source native GUID mappings remain private. No title/path-name similarity, branch name, area label or pipeline name inference.

Each row has continuity/review/requirement/verification originals plus new delivery/defect/build metrics when qualified. Record can belong to multiple components: count once per component, once globally, retain overlap/unmapped count; do not sum rows. Component zero requires complete independent record population AND complete membership lookup for that selected component/window. Partial mapping gives observed subset counts/PARTIAL with unknown/unmapped totals; zero from an unsupported map is null. Global metrics remain meaningful independently of component mapping. Build repository/source revision alone supports repository scope, not component assignment; multi-component build failures are overlapping run evidence, not multiple independent failures. Original requirement metrics with no accepted component population projection remain system-level; component cells unavailable rather than repartition a global denominator.

## Deterministic findings and investigation rules

Finding fields: stable ID from full rule/scope/window + sorted evidence identities (canonical SHA256, not secret identity obfuscation), type, exact system/component/window scope, severity INFO/ATTENTION/HIGH, rule_id/version/config fingerprint, observed metric/reference identities, population/sample size, measured value, threshold/comparison, source/capability/completeness, limitation codes, and fixed recommended investigation IDs. Severity is investigation attention only; distinct from Bug priority/severity, Git continuity label, acquisition failure and correctness. No incident probability/causality/readiness/employee judgment.

Eligibility: old metric findings require that source's accepted availability/completeness/qualified lookup criteria, with original reference time prominently retained. New absolute count/duration findings require known required field/units, positive qualified evidence and stated population completeness; incomplete observations may generate INFO evidence-limit notices but not total/trend claims. Comparative finding requires shared fully qualified comparison contract; no score is generated. Rule thresholds below are explicit defaults in policy `engineering-review-rules-1`, configurable only via recorded policy/version. All findings persist exact supporting refs and all exclusions/limitations; dedupe once per `(rule,scope,window)`, no response-order choice. Sort severity HIGH then ATTENTION then INFO, rule ID, full scope, window, finding ID; this orders attention, not people or composite health.

| Type / rule | Deterministic condition / severity | Fixed investigation intent |
| --- | --- | --- |
| CONTINUITY_CONCENTRATION / ER01 | Existing concentration risk HIGH→ATTENTION, CRITICAL→HIGH, retain its historical reference; no recomputation | Inspect file/contributor support, seek knowledge outside sources, inspect handover/docs |
| LOW_REVIEW_COVERAGE / ER02 | Complete supported mapped merged PR sample>=4, coverage<0.5→ATTENTION, exact distinct count | Inspect qualifying/excluded events and collection scope, investigate observed unreviewed changes |
| TRACEABILITY_GAP / ER03 | At least one existing qualified MISSING gap with complete supported endpoint lookup→ATTENTION | Inspect explicit intent/change associations and missing hop, check mapping/source scope |
| VERIFICATION_GAP / ER04 | Known selected test with complete supported lookup and no qualified observation→ATTENTION; unsupported lookup generates only INFO limitation | Inspect exact test version/target, exclusion reasons and available observations; do not claim missing testing |
| DELIVERY_AGING / ER05 | Known open age>=30d→ATTENTION,>=90d→HIGH; exact item state/creation at inventory boundary | Investigate oldest supporting work/PR records and censoring/selection, not employee productivity |
| DELIVERY_FLOW_DEGRADATION / ER06 | Comparable complete WI-cycle or PR-lead median samples>=4 each, current>previous and relative delta>=0.25→ATTENTION; previous0 suppresses relative trigger | Inspect duration samples/type policies/history and changed mix; state increased duration without cause |
| AGED_DEFECTS / ER07 | At least one qualified open Bug>=30d→ATTENTION,>=90d→HIGH; unknown-age items separately reported | Inspect explicit defect lifecycle/priority evidence and unresolved mappings |
| DEFECT_INFLOW_EXCEEDS_RESOLUTION / ER08 | Complete matching Bug event population, opened−resolved>=1→ATTENTION | Inspect both event populations/reopens/removals; do not equate difference to backlog growth |
| BUILD_FAILURE_CONCENTRATION / ER09 | Complete explicitly scoped terminal build sample>=4, FAILURE/known-terminal denominator>=0.25→ATTENTION,>=0.5→HIGH | Inspect run/result/pipeline scopes and qualifying duration; never equate builds to product quality |

No threshold finding proves absence of issues when not triggered. Missing inputs/capabilities generate first-class completeness/INFO notices with no fake measured0; counts of findings are not a health score. Fixed templates may say “Cycle time increased in the selected comparison windows,” never “team overloaded.” Investigations address artifacts/coverage/conditions; no hiring/firing/individual evaluation or prescriptive organizational action.

## Completeness and comparison presentation

Every dimension has provider/profile and operation, selection/population, field/history/mapping capability SUPPORTED/UNSUPPORTED/UNKNOWN, collection COMPLETE/PARTIAL/FAILED, observed/eligible/unknown/excluded counts, reference window/instant, retrieval boundary/skew, limit/conflict/failure reasons and metric OBSERVED/PARTIAL/UNAVAILABLE. Those axes never substitute for runtime governance PLANNED/VERIFIED/MANUAL. Show no delivery/quality/build input as UNKNOWN capability + UNAVAILABLE; deferred deployments as UNSUPPORTED/DEFERRED_BY_DESIGN. Failed no-positive acquisition=null; complete empty eligible counts=0 only for defined count metrics, ratios/quantiles=null. Present unknown/unmapped units on summary and drilldown rather than hide them behind a green badge.
