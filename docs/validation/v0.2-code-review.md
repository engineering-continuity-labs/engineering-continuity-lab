## Findings

### R1 — MAJOR: imported aggregates need not agree with retained evidence

Status: RESOLVED after re-review; original finding retained below.

Location: `ui/dist/model.js`, `validateReviews`, lines 20–44. Owning roles: QA and Developer; ECL-FR-219 / ECL-AC-221 and the completion design's numerical consistency requirement.

The validator validates PR/events and aggregate arithmetic independently. It never checks whether component membership, covered PRs, qualifying units, exclusions, or unreviewed references follow from retained PR paths and effective review events. A report whose events have all been deleted still imports with nonzero coverage and reviewers, and is rendered/exported as validated evidence.

Concrete independently executed reproduction:

```javascript
import sample from './ui/dist/eshop-reviews.js';
import git from './ui/dist/eshop-report.js';
import {validateReport} from './ui/dist/model.js';
const report = {...git, report_version:'2.0', review_evidence:structuredClone(sample)};
report.review_evidence.provenance.pull_requests.forEach(pr => pr.reviews = []);
validateReport(report); // accepted
// src still reports covered_pull_requests:3 and reviewer_units:{eerhardt:2,maddymontaquila:1}
```

Required resolution: reject aggregates inconsistent with the normalized evidence. For the recorded directory strategy, reconcile derived component mapping, effective-state qualification, covered/unreviewed PR populations, reviewer units and exclusions. Preserve documented compatibility for early reports without depth while still rejecting evidence-level contradictions that are decidable without mapping. Add regression cases for removed/changed review events, wrong component membership/denominator, and inconsistent exclusion/unreviewed populations. Re-review after the fix.
