## Findings

### R1 — MAJOR — snapshot shortcut falsely reports observed commit membership missing

**RESOLVED.** Focused review confirms snapshot paths with observed PR_COMMIT membership now emit PARTIAL/UNRESOLVED_NORMATIVE_SEGMENT without inventing commit-to-snapshot ownership; original absent membership semantics remain. Added `test_ac334_snapshot_on_pr_with_commits_has_unresolved_not_missing_segment` passes.

Owner: Developer / QA. Requirements: ECL-FR-312–313, ECL-FR-325; AC334; D303/D305.

In `analysis/traceability.py`, every path containing PR_PATH appends `ctx.gap(pr, PR_COMMIT)` without checking recorded membership. Add a valid PR snapshot-path observation to BASE PR-51, which already has direct PR_COMMIT links to a and b. Each snapshot shortcut reports PR_COMMIT MISSING/NO_OBSERVED_LINK even though those links are present and retained. The existing AC334 test covers only PR-54's genuinely empty membership, missing this combination.

Required repair: retain the short shortcut's PARTIAL full-chain label and explain the unresolved normative commit segment without asserting missing membership when membership exists. Do not guess which PR commit owns a PR snapshot path. Add regression coverage for observed membership plus snapshot paths and for genuinely absent/incomplete/unavailable membership.

### R2 — MAJOR — lookup provenance scope is unchecked before negative assertions

**RESOLVED.** Focused review confirms lookup endpoints are checked against their boundary's repository and relevant provider/instance/project scope; incompatible evidence becomes UNKNOWN capability with sanitized diagnostic and UNAVAILABLE gaps. `test_ac313_wrong_scope_lookup_cannot_prove_negative` covers the reproduced wrong-instance negative assertion and order invariance.

Owner: Developer / QA; Architect only if contract changes are necessary. Requirements: ECL-FR-303, 313, 319; NFR303/310; AC324–325; D302/D305/D306.

`normalize` verifies direct-link and work-item scopes against observation boundaries but does not verify a LookupEvidence endpoint against its boundary. Add a second boundary with another provider/instance/project but the same repository alias, mapping/filter/join contract; point BASE PR-54's COMPLETE PR_COMMIT lookup at it. Derivation still emits MISSING/NO_OBSERVED_LINK for PR-54 in the original provider instance. A lookup in another source scope cannot establish an in-scope complete absence. Missing boundary IDs become unavailable, but wrong valid boundary scopes slip through.

Required repair: validate relationship lookup endpoint ownership against boundary provider/instance/project/repository and the declared explicit mapping rules. Quarantine incompatible lookup evidence with a safe diagnostic and UNAVAILABLE affected scope; never preserve complete negative authority. Add wrong-provider/instance/project/repository fixtures, retaining legitimate provider-neutral Git joins.

### R3 — MAJOR — existing-owner projections silently replace source boundaries

**RESOLVED.** Focused review confirms Git projection requires explicit matching History/boundary selected revision. Review projection requires matching source provider/repository/query/retrieval time and rejects unapproved relabelling with a fixed safe error. Added `test_ac325_history_projection_rejects_revision_relabelling` and `test_ac333_review_projection_rejects_source_provenance_relabelling` pass. Positive nonmutating projection fixtures now use compatible metadata. Explicit private alias mapping remains a future gate rather than silently overwriting source identity.

Owner: Solution Architect for any new mapping contract, then Developer / QA. Requirements: ECL-FR-303/319; NFR303/308; AC325/333; D306/D308.

`project_reviews` ignores `ReviewEvidenceCollection.provenance` and emits PR references/path observations under the supplied boundary's provider/repository/query/time even if the source provenance is different. `project_history` likewise ignores `History.revision` versus the supplied boundary revision. The existing history projection test uses history revision a*40 with boundary revision d*40 and accepts the mismatch. Caller-supplied metadata can therefore silently relabel evidence from a different repository/provider or fixed Git snapshot, contrary to explicit source ownership and compatible-boundary joins.

Required repair: validate source provenance/revision compatibility before projection, or introduce an explicit owning-role-approved source-to-safe-alias mapping contract that retains the source collection identity/timestamps rather than overwriting them. Reject unapproved incompatible projections with fixed safe errors. Add positive approved-projection and negative provider/repository/boundary/revision cases; do not publish raw private source metadata to repair the provenance gap.

### R4 — MAJOR — excluded-population counts are actually link counts

**RESOLVED.** `_Context` now retains a set of scoped out-of-population references; each metric counts distinct relevant artifact kinds, with nonmerged PRs excluded only from merged-PR coverage and changed occurrences mapped to their component. `test_ac326_excluded_counts_are_dimension_specific_distinct_artifacts` confirms BOUNDARY PR/WI exclusions 0, commit exclusion 1, payments change exclusion 1, catalog exclusion 0, and repeated/alternate routes cannot inflate those counts. Reviewer inspected the repair and executed the final offline suite independently.

Owner: Developer / QA. Requirements: ECL-FR-326; AC326; D307.

All metrics use the same `ctx.excluded` as excluded_count. That variable increments once per excluded link, not per distinct artifact in the metric's dimension. In BOUNDARY, removing commit d and its path excludes PR-53→d and d→path: every metric reports excluded_count=2, including PR and WI dimensions whose own populations were not excluded. Commit exclusion is one distinct commit, not two relationships. More alternative routes increase the count further without changing excluded artifacts.

Required repair: compute dimension-specific distinct scoped excluded artifact/change populations, distinguish relation diagnostics from artifact counts, and keep unavailable population counts explicit rather than guessing. Add exact BOUNDARY and duplicate-route exclusion oracles for PR/commit/WI/component dimensions. Coverage denominator honesty must extend to excluded counts as well as numerator/denominator.
