# v0.3 Report v3 QA Plan

**Role:** QA Engineer. **Status:** ACCEPTED pre-development plan; implementation results and evidence are recorded in `docs/validation/v0.3-report-v3-verification.md` and `specs/v0.3/traceability.md`.

## Oracles and test surfaces

- Python API tests in `tests/test_traceability_reporting.py` use `base_fixture()` and `derive()` as the only BASE source. Never hand-copy expected metrics into a payload fixture.
- A generated/captured synthetic v3 report is consumed by browser model tests. Browser fixtures use only project-owned synthetic aliases and identifiers.
- Python imports re-derive results; browser checks the same public schema and semantic invariants. Both reject unknown versions and types.
- Existing `tests/test_traceability.py`, `tests/test_review_evidence.py`, `ui/tests/model.test.js`, `ui/tests/reviews-ui.test.js`, and Pages static tests remain regression gates.

## Required Python checks

1. Exact v3 envelope and serializer field allowlists; preserve `model: experimental-v0.1`, Git fields, optional review evidence, and optional section rules.
2. `base_fixture()` serialization is byte-identical across repeated calls and reversed input order for every unordered collection; path node/support order is retained.
3. Parse, validate, reconstruct, and reserialize BASE to equivalent canonical JSON; retain direct/provider, direct/source, and derived origins plus support identities.
4. BASE metrics derive as PR intent 3/4, commit intent 4/4, work-item implementation 2/3, payments 2/2, tests 1/1, catalog 1/1; `PR_PATH_ONLY` round-trips its shorter snapshot path without creating commit/change units.
5. Duplicate boundary/reference/link/path/metric/diagnostic rejection or normalization behavior; duplicate canonical paths must not be accepted.
6. Bad link endpoint kinds, illegal origin (including direct `PATH_COMPONENT`), unknown relation, unknown artifact kind, malformed scoped reference, abbreviated/invalid commit hash, and unsafe path are rejected.
7. Invalid normative paths, missing/reordered hops, repeated endpoint/cycle, unresolved/extra support reference, and derived WI_COMPONENT without a supported path are rejected.
8. `MISSING` without exact scoped supported COMPLETE lookup, `VERIFIED` without every required hop, and unexplained MISSING/VERIFIED contradiction are rejected.
9. Coverage numerator/denominator/count bounds, exact ratio, zero denominator, unavailable/null semantics, unknown/excluded counts, boundary presence/reference, and dimension/component shape are checked.
10. Invalid collection/capability/trace statuses; COMPLETE/PARTIAL/FAILED with SUPPORTED/UNSUPPORTED/UNKNOWN combinations; FAILED with no useful evidence yields UNAVAILABLE and never MISSING.
11. Missing, unknown, and duplicate boundaries are rejected; every observation/lookup/gap/path/metric boundary reference resolves.
12. Unsafe provenance sentinels for PATs, bearer/auth headers, passwords, cookies, credential-bearing URLs, raw response fields, local paths, and unapproved labels are rejected or unrepresentable and never echoed in errors.
13. Unknown `schema_version`, report version, artifact kind, relation kind, origin, status, and reason fail closed.
14. v1 Git-only and v2 review compatibility; v3 trace only; v3 review plus trace; v3 partial evidence; v3 FAILED with no usable trace evidence; v3 without the optional section.
15. JSON decoder and encoder use no NaN/Infinity; exact canonical compact JSON and object-key ordering are stable.

## Required browser checks

1. Existing v1 and v2 model/import/export cases continue to pass unchanged.
2. Validate/export/import the Python-generated BASE v3 report and compare `traceability_evidence` structurally exactly.
3. Accept v3 traceability with and without review evidence, v3 PARTIAL, and v3 FAILED with no usable evidence; leave absent traceability absent.
4. Reject malformed section/schema version, unsupported future report/schema/artifact/link values, bad link endpoints/origins, unresolved supports, illegal/repeated path nodes, unqualified MISSING, incomplete VERIFIED, and contradictory states.
5. Reject numerator greater than denominator, wrong ratio, numeric ratio at zero denominator, and null ratio for an available nonempty metric.
6. Browser export/import must not drop, rename, or rewrite traceability values or existing review/Git fields.
7. Load an invalid report after a valid one and verify the active report is not replaced; the static app must still make no hosted network request or upload.

## Execution and evidence gates

Run focused Python serialization tests and focused Node model tests immediately after their respective edits. Before review, run full unittest discovery, strict mypy, all Node tests, both JS syntax checks, package wheel build, and `git diff --check`. Record actual commands/results and residual gaps in the verification record. Do not claim a case VERIFIED solely because the schema document says it should pass.

## Corrective QA handoff

The initial independently reproduced findings and role handoffs are retained in `v0.3-report-v3-review.md`. Corrective checks use a shared 131-case malicious wire corpus plus generated positive fixtures for all synthetic variants, UNKNOWN, multiple boundaries/diagnostics, microsecond incompatibility, incompatible lookup scope, leap dates, Unicode, approved path names and equivalent ISO spellings. Compare against the previous implementation to confirm meaningful regressions. The final human re-review is required by the user's explicit instruction; passing automation does not constitute independent approval of corrective Developer work.
